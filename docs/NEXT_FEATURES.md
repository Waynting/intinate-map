## 🚀 建議開發功能（依優先級排序）

### Priority 1: 核心 CRUD 功能 ⭐⭐⭐⭐⭐

#### 1.1 新增場所頁面 (`/places/new`)
**重要性:** 🔴 高 - 用戶無法自行新增場所
**工作量:** 2-3 小時
**描述:** 讓用戶可以新增未在資料庫中的場所

**功能需求:**
- 表單欄位:
  - 場所名稱 (必填)
  - 類型選擇 (飯店/汽車旅館/民宿)
  - 地址 (必填)
  - 座標 (lat/lng) - 可從地址自動獲取或地圖點選
  - 隱私標籤多選
- 地址自動完成 (Google Places Autocomplete)
- 地圖上點選座標
- 表單驗證
- 提交後重定向到場所詳情頁

**技術要點:**
- 使用 Google Places Autocomplete API
- 整合 Google Maps 可點選地圖
- Prisma 創建場所記錄
- createdBy 關聯到當前用戶

---

#### 1.2 編輯場所頁面 (`/places/edit/[id]`)
**重要性:** 🔴 高 - 無法修正錯誤資料
**工作量:** 1-2 小時
**描述:** 編輯現有場所資訊

**功能需求:**
- 預填現有資料
- 與新增頁面相同的表單結構
- 權限檢查（擁有者或管理員）
- 更新後重定向到詳情頁

**注意事項:**
- 政府資料來源的場所：僅管理員可編輯
- 用戶創建的場所：擁有者或管理員可編輯

---

### Priority 2: 管理後台 ⭐⭐⭐⭐

#### 2.1 檢舉管理頁面 (`/admin/reports`)
**重要性:** 🟠 中高 - 管理員需要處理檢舉
**工作量:** 3-4 小時
**描述:** 管理員查看和處理用戶檢舉

**功能需求:**
- 檢舉列表（表格或卡片視圖）
  - 顯示：檢舉類型、目標（場所/評論）、檢舉者、狀態、時間
  - 過濾：狀態（pending/approved/rejected）、類型
  - 排序：時間、類型
- 檢舉詳情對話框
  - 顯示完整檢舉資訊
  - 顯示被檢舉的內容（場所或評論）
  - 操作按鈕：批准/拒絕/刪除
- 檢舉統計儀表板
  - 總檢舉數
  - 待處理數量
  - 各類型分布
  - 趨勢圖表（可選）

**技術要點:**
- 使用 reportsApi.list() 和 getStats()
- 權限檢查（admin/moderator only）
- 狀態更新使用 reportsApi.updateStatus()

---

#### 2.2 用戶管理頁面 (`/admin/users`)
**重要性:** 🟡 中 - 管理用戶帳號
**工作量:** 2-3 小時
**描述:** 管理員查看和管理用戶

**功能需求:**
- 用戶列表
  - 顯示：Email、角色、註冊時間、評論數、檢舉數
  - 搜尋：Email
  - 過濾：角色（user/admin/moderator）
- 用戶操作
  - 變更角色
  - 停用帳號（待實現後端）
  - 查看用戶活動（評論、檢舉）

**需要新增的後端 API:**
- GET /api/admin/users
- PATCH /api/admin/users/:id (更新角色)
- DELETE /api/admin/users/:id (停用帳號)

---

### Priority 3: 用戶體驗增強 ⭐⭐⭐

#### 3.1 個人中心頁面 (`/profile` 或 `/me`)
**重要性:** 🟡 中 - 用戶查看自己的活動
**工作量:** 2-3 小時

**功能需求:**
- 個人資訊
  - Email
  - 註冊時間
  - 角色徽章
- 我的評論列表
  - 顯示評論的場所、評分、時間
  - 快速跳轉到場所詳情
  - 編輯/刪除評論
- 我創建的場所（如有）
  - 顯示場所名稱、類型、評論數
  - 快速編輯/刪除
- 統計數據
  - 總評論數
  - 平均評分
  - 創建的場所數

**技術要點:**
- 使用 reviewsApi.listByUser(currentUserId)
- 使用 placesApi.list({ createdBy: currentUserId })

---

#### 3.2 收藏功能
**重要性:** 🟡 中 - 用戶收藏喜歡的場所
**工作量:** 3-4 小時

**功能需求:**
- 收藏按鈕（在場所卡片和詳情頁）
- 我的收藏頁面 (`/favorites`)
- 收藏列表顯示

**需要新增:**
- 後端：Favorite 模型和 API
- 前端：收藏按鈕組件和頁面

**資料庫 Schema:**
```prisma
model Favorite {
  id        String   @id @default(uuid())
  userId    String
  placeId   String
  createdAt DateTime @default(now())

  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  place     Place    @relation(fields: [placeId], references: [id], onDelete: Cascade)

  @@unique([userId, placeId])
  @@index([userId])
  @@index([placeId])
}
```

---

#### 3.3 地圖邊界搜尋
**重要性:** 🟡 中 - 改善地圖性能
**工作量:** 2 小時

**功能需求:**
- 只載入當前地圖可視範圍內的場所
- 拖動/縮放地圖時自動更新
- 顯示「重新搜尋此區域」按鈕

**技術要點:**
- 使用 Google Maps bounds API
- placesApi.list({ bounds: { ne, sw } })
- 後端已支援 bounds 參數

### Priority 4: 進階功能 ⭐⭐

#### 4.1 照片上傳
**重要性:** 🟢 低中 - 增加場所資訊豐富度
**工作量:** 4-5 小時

**功能需求:**
- 場所照片上傳（新增/編輯場所時）
- 評論照片上傳（撰寫評論時）
- 照片展示（輪播或網格）

**需要新增:**
- 檔案上傳服務（本地或雲端，如 Cloudinary）
- Image 模型
- 圖片壓縮和優化

**資料庫 Schema:**
```prisma
model Image {
  id        String   @id @default(uuid())
  url       String
  placeId   String?
  reviewId  String?
  uploadedBy String
  createdAt DateTime @default(now())

  place     Place?   @relation(fields: [placeId], references: [id], onDelete: Cascade)
  review    Review?  @relation(fields: [reviewId], references: [id], onDelete: Cascade)
  uploader  User     @relation(fields: [uploadedBy], references: [id], onDelete: Cascade)
}
```
